在 Codex 中使用

CLI 负责执行，Skill 说明怎样理解资料、核对范围和组织结果。
内部用户通过独立访问码查询服务器历史数据，公开演示使用合成资料。

一行命令，打开完整工作台

一行安装并打开原版工作台 · 0.2.12
python3 -c "import pathlib,venv,os,subprocess;d=pathlib.Path.home()/'.valuation-agent/workbench';venv.create(d,with_pip=True);p=str(d/('Scripts/python.exe' if os.name=='nt' else 'bin/python'));subprocess.run([p,'-m','pip','install','valuation-agent[excel] @ https://codeload.github.com/yuguangtongchen1/valuation-agent/zip/156aca03aa2d848227caddb57d0b53023105c5e3'],check=True);subprocess.run([p,'-m','valuation_agent.cli','launch'],check=True)"

将命令交给 Codex 执行，或直接在终端运行。Windows 将开头的 python3 换成 py。需要 Python 3.9+、网络连接；无需 Git、Node.js 或自行部署服务器。

首次打开后输入管理员单独发给你的访问码。历史数据库留在服务器，按权限查询；请保持启动进程运行。飞书导入时让 Codex 运行 valuation-agent feishu-setup，缺少 CLI 会自动安装；需 Node.js（npm/npx）及你自己的飞书授权。

把任务交给 Codex

将以下提示词粘贴到 Codex。它会先读取公开仓库中的 Skill，再按你的资料和任务执行。



准备自己的数据
  • 新报价：带有物料或服务名称、规格描述、数量、单位、单价或金额的文件。
  • 访问码：由管理员单独提供，可撤销；不要提交到公开仓库。历史合同与 BOM 按权限从服务器查询。
  • 飞书来源：提供你有权限访问的文件或表格链接。需要使用者自己的飞书授权与读取工具。
  • 归类规则：已有类目、采购认可的别名和禁止混比的情形，都可以作为规则输入。
品牌、型号和规格没有写明时，保留缺项。整包报价与单项单价分别检索；不同计价单位不直接合成价格区间。


从接入到比价表
audit核对来源关联和人民币展示覆盖
import读取报价和历史资料，保留来源关系
classify按用途、工艺、材料和配置建立类目
search查项目、装置或具体 BOM 子件
compare比较规格、范围、数量与计价单位
report可选文档输出，默认不附加分析
demo使用独立合成案例验证操作


检查结果时，看这几件事
  • 参考对应的是同一个物料、相似配置、整个服务包，还是其中一部分？
  • 尺寸、材质、型号、施工范围和计费单位有哪些差别？
  • 历史供应商、原项目和明细是否能回查？
  • 没有参考，是资料未收录、价格不明确，还是现有证据不足以比较？
输出的是基于所接资料的历史参考。数据覆盖、字段提取和可比性仍需核查；演示页面不代表已经连接生产后台。
