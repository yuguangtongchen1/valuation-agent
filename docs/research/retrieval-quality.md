# 检索质量与数据库优化验收

## 已实施

同源排除使用身份倒排索引和图遍历：URL、文件标识、哈希、报价家族、采购事项之间的传递关联均参与排除，旧版本可作为关联桥梁但不可成为当前价格样本。保持原始行顺序。

远程 compare 返回 retrieval_corpus：historical_rows = same_source_rows + other_inactive_version_rows + retained_rows；retained_rows = eligible_price_rows + other_retained_rows。这些是资格统计，不是准确率、召回率或原件视觉审计覆盖率。

每次检索的 retrieval_passes 区分扫描行、价格角色排除、同源或已选排除、语义未匹配、候选、已处理重复和超出展示上限的候选。超出上限的候选尚未完成展示阶段去重，不能当作独立样本数。空名称及超长名称明确报错，不再返回“检索完成但无参考”。

## 后续实验，不代表已经实现

1. 切片：按项目→合同→报价版本→装置/服务→计价行→组合子件组织；图片按锚定行和图示部位关联，父项总价不可复制给子件。
2. 向量/张量：仅将采购对象、功能、工艺及规格编码为候选检索特征；原始数值、来源和价格保持结构化。先建立人工核定样本，再比较词法、向量及混合召回；不因为术语相似就判为可比价格。
3. 召回：词法、细类、近邻类、组合子件各自保留渠道；同源与非当前版本在排序前排除。与全量结构化扫描基线比较漏召回，不仅比较返回条数。
4. 重排：核心交付对象和范围优先，随后比较材质、工艺、型号、尺寸、单位；整包和部分子件显式保留范围。金额不作为相似度依据。
5. 智能理解：模型用于非标表头、图片标注和同义表达判断；输出字段必须有原文、单元格或图片部位证据。尺寸不可依据透视效果图估算。
6. 架构：原件不可变，抽取结果、人工确认、分类和索引各自版本化；报价幂等导入，供应商关联独立于名称相似度。

## 质量门槛

建立逐行标注集合，包括正确同类、整包包含、仅子件相似、不相关、无证据。报告 Recall@K、前列准确率、同源泄漏、旧版重复、单位不兼容比例及 P50/P95 延迟。没有标注集不声称召回完整；没有 Windows 真机不声称 Windows 验收通过。回归保留环形灯/灯带、施工图/深化设计、运营/搭建、图文/图片尺寸等失败案例。
