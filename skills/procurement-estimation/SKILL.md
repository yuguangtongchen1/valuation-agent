# 采购估价

先理解实际交付内容，再比较价格。Codex 负责逐份理解非标原件、辨认字段和复核候选；`valuation-agent` 负责归一、规则归类、检索和表格输出，不自带 OCR 或远程模型；飞书读取需安装并授权官方飞书 CLI。

## 开始

使用用户已授权的文件或只读数据源。已有授权和任务范围内直接完成，不逐步索要确认；关键字段有歧义时保留原文和缺口，继续处理不受影响的记录。原件和用户数据留在用户控制的位置，公开仓库不包含真实合同、报价或凭据。

有 CLI 时先运行 `valuation-agent --help`。未安装时使用 Python 3.9+ 和独立环境：

```sh
python3 -m venv .venv
.venv/bin/python -m pip install 'valuation-agent[excel] @ git+https://github.com/yuguangtongchen1/valuation-agent.git'
```

随后用 `.venv/bin/valuation-agent` 替代下方的 `valuation-agent`。Skill 不需要私有仓库或其脚本。

## 界面交付约束

使用原版完整 React 工作台，不新写简化上传页，不替换原有三级步骤、分组报价表、右侧比价、详情与规格对照、导出样式。访问码只作为首次激活步骤；激活后由 `launch` 提供包内原版构建。用户仍看到简化页面时，升级至少0.2.10，结束旧版本机进程，再启动新URL；只刷新旧服务不会升级程序。已有有效访问码继续使用，不重复签发。

## 用户拿到安装指令和访问码时

用户要求直接使用/打开界面时，安装带 Excel 依赖的最新版，然后运行 `valuation-agent launch`，保持进程运行并打开输出的 localhost URL。不要只展示 help、跑 demo、生成 JSON 后结束。首次无配置时界面显示访问码输入；已有配置直接进入上传报价。界面内可以上传、整单比价、看历史参考、打开合同明细、导出 Excel。

访问码为 `VA1.` 开头、可撤销的个人内部凭证，不能写进公开 Skill、安装脚本、仓库或网页 URL。用户已经在聊天提供时，用进程标准输入交给 `valuation-agent activate`，不回显；或读取用户给定的本地访问码文件 `valuation-agent activate --file <path>`。不把码放进命令参数，也不将某人的访问码共享给其他人。若用户未提供，只打开激活页，不捏造凭证。

Windows 解释器用 `py`、虚拟环境 `.valuation-env\Scripts\python.exe`；macOS/Linux 用 `python3`、`.valuation-env/bin/python`。安装 `valuation-agent[excel]`，不是仅基础包。包内自带网页，不需要 Node 或另取前端目录。首次选择可用端口，后续保留相同端口以维持浏览器报价记录；远程执行环境自动打开浏览器失败时，明确给出 URL 并打开本机浏览器。服务应持续运行直至用户完成。

## 内部服务器模式

管理员已提供访问配置时优先用 `--remote /path/to/remote.json`。使用者只需安装 CLI 和 Excel 依赖；不用下载历史数据库。不要让用户把 token 写入聊天、参数或仓库，只读取管理员已放好的配置路径。不要把离线副本当作服务器实时数据。

```sh
valuation-agent run ./quotation.xlsx --worksheet 报价 --remote /path/to/remote.json --output-dir ./比价结果
valuation-agent search '用途 型号 规格' --remote /path/to/remote.json
valuation-agent contract <返回的record_id> --remote /path/to/remote.json --out ./合同明细.json
```

`run` 只生成两张工作表的 Excel 和 JSON，不生成采购建议。远程模式只发送检索字段，原文件不上传；返回的历史参考仍属于内部数据。401 联系管理员核对凭证，403 核对权限，429 稍后重试，503 等当前查询完成；不要循环重试或绕过 HTTPS。Windows 使用 `py` 和 `.venv\Scripts\valuation-agent.exe`，macOS/Linux 使用 `python3` 和 `.venv/bin/valuation-agent`。

## 理解并导入

遇到合同、PDF、DOC/DOCX、图片、合并表头、多个报价区块时，先读 [schema.md](references/schema.md)。直接复用已有原文、表格和 OCR 缓存；只有具体字段看不清、疑似错列或漏行时才回原页/图片。没有识别缓存且当前工具支持时再提取，不把任务调整当作重新扫描的理由。

逐份识别项目背景、装置/模块、真实物料或服务行、规格子行、备注、合计、版本及附表。表头可以合并、换位置或跨行，不能固定列号或把“材料名称/规格”当未知后改取备注。“2个人工”可能是备注，项目名称也不等于物料名。保留每张附表及未标价、零价的真实子行。

- 每个真实明细行一条 JSON，原始列和值保留在 `source_original_fields`；拆开的名称、型号、规格记录拆分依据和原件位置。
- 保存“项目→区域/工作包→装置/组合→子BOM”的包含关系，层级按原件，不固定三级。同合同不意味着所有物料都属于同一装置。
- 只有整项报价时保留一条 `whole_scope_quote`，关联背景、交付范围和原文；不虚构子项单价、不虚构数量或子件单价。
- 数量、单位、单价、小计、日数、每套组成及包价分别保留。先确认实际计算式，不能把所有表都套成“数量×单价”。
- 实物数量和计费数量分开：例如18片玻璃按47平方米计价，不能用片数替换面积。原件核实后的 `verified_billing_context` 保留两种数量单位、固定人民币总额、包含服务及结算条件；Excel“单价依据”同步展示。固定总额与量价乘积存在原件明确的差异时，保留双方，不重算覆盖，也不自动提升为可直接比价。
- 归类模板仅是类目和字段规范；模板零值、示例报价及新测试单不进入历史成交库。

标准 CSV/JSON，或已明确选表和表头的 XLSX / XLS，可直接导入：

```sh
valuation-agent import ./quote.json --out ./normalized.json
valuation-agent import ./quotation.xlsx --worksheet 报价 --out ./normalized.json
valuation-agent classify ./normalized.json --out ./classified.json
```

CLI 读取 Excel 公式的已有缓存值，不执行公式；多表逐张明确选择后由模型关联。非标资料先理解并生成 JSON，再导入，不声称 CLI 能直接识别所有合同。

## 检索与复核

```sh
valuation-agent search '型号或物料 规格' --history ./history.json --limit 20 --out ./search.json
valuation-agent compare ./normalized.json --history ./history.json --out ./comparison.json
```

历史 Excel 可用 `compare --history-worksheet 表名`，`search --worksheet 表名`。已有完整兼容 Data Hub 时将 `--history ./history.json` 换为 `--data ./private-data`；二者互斥，`--data` 不是任意 JSON 文件夹。连接飞书等来源须用当前可用的授权连接器，只读获取后再归一；本地缓存查询不能说成实时遍历了飞书。

对整张新报价逐行检查结果，不能第一次名称未命中就结束。先用途和实际功能→同层技术细类→型号、材质、尺寸、工艺和组合→交付与计费范围；再扩展相似对象、明确子件及工艺线索。名称别名帮助召回，不证明同物同价。用模型阅读原描述、候选规格和排除条件，对缺召回继续分解工艺/配置关键词检索，但不把无关候选凑成参考。

明确区分：直接可比、有规格差异的同类、整包、部分工作、组合子件、工艺参考。缺参数与参数明确不同要分别表达；相异材质/型号/范围应指出差异。整包或局部参考不判断整项高低，也不把一个包价重复计到所有子项。

归类借鉴“定义先行、细项优先、同层比较、组合看实际功能”的方法，不将海关编码规则机械当成采购价格算法。类别深度不固定；项目实例树、归类树和价格属性分开保存。

## 金额与建议

财务已确认的台账人民币金额直接关联，不反复审核税费或外汇口径；合同价格保留实际原币。明确 `万元` 才乘10,000，保留原值和单位，已归一金额不重复转换。外币万元转换后仍是原币，不能裸标 CNY；人民币单项价需要明确财务换算依据，不能用合同人民币总额反推单项汇率。详见 schema 金额字段。

复核状态是源文核对的结果，不能为获得“偏高/偏低”结果批量改成已核。`line_fields_verified_price_scope_pending` 只说明字段读数已核，价格适用范围仍待核：可以展示有来源的参考，不能标成直接可比。即使名称、单位相同且未检出差异，也不能绕过此状态。单条历史报价仅是某次交易参考；即使多个项目有价格，也先排除重复证据、旧版本和范围差异。

最终默认只交付比价表，不在表格下附加采购建议、报价分析或长篇说明。表内保留当前物料与规格配置、参考物料、供应商、人民币价格、计价方式、差异、整包/子项范围和无参考原因。来源完整存入JSON和详情，原件页行定位不用塞进主表。

`report` 是兼容的可选文档命令，仅当用户明确要求分析或报告时调用。`demo` 使用合成数据，必须与真实历史分开。

币种须以原文明示为准，AUDIO 等名称不能按 ISO 代码前缀识别为澳元。财务比例折算只改变人民币展示，不升级成交或可比性状态；同文件本期付款比例不能称为整份 BOM 的付款分摊。行政报批、设计编程、设备采购、安装人工和复合服务分别归类，名称不明时保留待确认。

## 报价层级与版本

同一原件关联多个台账或项目，不算多个独立历史价格样本。比较前按来源及报价版本识别重复；多项目价格统计至少需要两个项目、两个独立来源，不能用复制记录扩大样本数。来源修正应保留原始提取值和原件定位，并验证 BOM 与服务查询快照均已更新；本地重建不等于远程部署完成。


分项单价与有来源的整包总额分别检索和展示；整包不能充当单件单价。同一采购的城市方案、盖章版本可分别查看，按经济采购事项去重，不作为独立成交样本。

按服务类型和采购对象归类，品牌和项目背景不代替技术类别。数字内容、人员运营、设计、拍摄、设备采购和租赁分别判断。组合子件仅作部分参考；缺参数不代表一致。用户授权且数量与总额明确对应时，可计算总额÷数量，保留两位小数并标记计算值，不冒充原始单价。

逐行检查未命中和弱参考：区分未收录、漏召回、参数不足、缺分项价格、范围不同及非独立计价；无命中不能推断完全非标。真正没有附表时按服务描述和整项金额归档，不要求补不存在的附件；有附表但读不清时记录具体缺口。

完整兼容 Data Hub 可用 `valuation-agent audit --data ./private-data --out ./audit.json` 检查关联；通过不等于每个字段已核实或所有报价可比。

对于原件未标币种、但完整单项服务与财务台账已精确核对的记录，可直接关联该项人民币台账总额作为小计展示；保留未知原币种，不伪造汇率或单价。直接关联必须限定来源行和相同完整范围，不得让其他子项继承整笔金额。零台账记录不能一刀切；只有明确核过的无人民币价格依据档案排除人民币价格召回，BOM和原价仍保留。`audit` 的 `unconverted_reference_rows` 用于检查可检索价格池的人民币展示缺口。

用户提供内部专用的 Python 启动文件并要求启动时，使用 Python 运行该文件并保持工作台进程运行。文件负责安装、激活及打开原版界面，运行前后均无需在对话中复制文件里的个人访问码。飞书导入沿用本机已授权的飞书 CLI。

## 飞书链接导入：主动修复新电脑环境

用户粘贴飞书链接或遇到飞书读取失败时，不只返回“检查授权”。使用官方指南：https://open.feishu.cn/document/no_class/mcp-archive/feishu-cli-installation-guide.md 。

1. 在运行估价工作台的同一台电脑、同一用户环境检查 `lark-cli --version`、`node --version`、`npm --version`。缺少 Node.js 时按 Node.js 官方安装方式安装 LTS（含 npm/npx），不要复制其他电脑的凭据。
2. 缺少飞书 CLI 时，主动运行 `valuation-agent feishu-setup`；它按官方指南安装 `npm install -g @larksuite/cli` 和 `npx -y skills add https://open.feishu.cn --skill -y`。若已有 CLI，复用它；缺少官方 Skills 时补装 Skills。权限不足不自动 sudo，给出具体失败环节。
3. 阅读已安装的 lark-shared Skill，运行 `lark-cli auth status --json --verify`。仅未配置应用时运行 `lark-cli config init --new`，不覆盖已有配置。未登录/授权失效时按官方指南和 lark-shared 发起用户登录；展示授权链接及二维码，用户完成后收尾登录并复查状态。登录必须由接收方自己的账号完成；不将估价访问码当飞书 token。
4. 授权正常后，用飞书只读命令读取用户原链接，区分文件无权限、缺 scope、链接类型不支持、网络失败和表格解析失败。不要反复重装；不要把所有异常都归为未登录。仅请求所需读取权限，不输出密钥。
5. 新安装后重启工作台以刷新 PATH，并重试原链接；核对实际导入的工作表与行数，继续比价、详情和导出。无法完成时报告具体阻塞，本地 Excel 上传仍可使用。

普通本地 Excel 工作流不依赖 Node.js 或飞书 CLI；只在使用飞书来源时补齐这些依赖。

## 指定用户的一次复制交付

管理员提供已有个人访问码文件后，用 `valuation-agent handoff --access-file <个人访问码文件> --out <私密命令文件>` 生成一行命令；Windows 加 `--windows`。不新建权限、不共用其他用户的码，不输出命令内容到日志，不提交生成文件到 Git。输出文件不得已存在。

接收方将专属命令粘贴给 Codex 后，直接执行安装、标准输入激活和 launch，保持进程运行并打开本机 URL，不再要求手动填写访问码。先检查 Python 3.9+；Windows 使用 py，macOS/Linux 使用 python3。若授权已过期或撤销，停止并联系管理员，不重复安装或绕过授权。飞书导入仍需接收方自己的飞书授权。专属命令内含凭据，仅私发给对应人员，不在官网展示。

## 左侧对话与原版工作台联动

用户在聊天提供新报价时，先读取文件并理解字段、规格和组合；普通 Excel 可直接使用，非标表先用模型整理成 `{ "project": "项目名称", "rows": [{"item_name":"名称","spec":"规格","description":"工艺","quantity":1,"unit":"套","unit_price":100,"subtotal":100,"currency":"CNY"}] }` JSON，保留 source_locator 和原文。不能凭空补金额或规格。

运行 `valuation-agent launch --input <报价文件绝对路径> --worksheet <需要时指定工作表>`，保持服务运行，将返回的带 `?handoff=1` 的 URL 在可用的 Codex 右侧浏览器打开；无法控制面板时提供 URL，不声称已打开。已有远程配置可加 `--remote <路径>`。激活后会自动加载，无需用户再次上传。

AI 理解与候选复核由当前 Codex 完成；工作台通过服务器查询历史参考，不内置自动聊天模型。用户纠正后，原子更新同一 JSON 文件，页面约两秒检测新版本并更新表格；修改会清除旧参考缓存。不要只改左侧回复而不更新文件。新的报价文件可以另启动实例，避免混淆项目。同步只读取明确指定文件，不监听用户全部聊天或磁盘。完成后实际检查页面明细和导出，不将成功启动等同于比价正确。

## 非标准表头与混合字段

服务费用表可能只有“费用说明、天数、付款金额”，没有单价列。仍需提取真实服务行，保留原表天数、人数及币种；天数不能自动视为人天计费数量，缺单位时不能倒算单价。正文与附件重复清单仅保留一份价格样本和多个定位，分组小计不算物料。分项与总计有差额时保留原值及差额，不凑数。


先读完整工作表的结构与数据，定位明细表头；顶部分类、明细行数、金额组成的汇总区不能当报价清单。CLI 0.2.15 可在 CSV/XLS/XLSX 前100行识别明确的明细表头，并保留前置汇总作为来源，不重复计价。它支持项目／展项、工程名称、制作工艺、项目特征、综合单价、原表金额等别名；这只是有边界的自动映射，不代表任意非标表都能自动理解。

- 项目／展项可能是背景或区域名。结合制作工艺识别实际采购对象：例如“展厅A”下的“亚克力UV画面”，不要只用展厅名称检索；保留原名与项目包含关系。
- 尺寸数量中的明确“2套”可提取数量和单位。预估数量必须标记预估；不得把尺寸、厚度或年份当数量。
- 一行含多组尺寸及数量时保留组合；没有子项金额，不拆分或均摊整行价格。厚度与尺寸共同作为规格，原文字段完整保留。
- 空白名称仅在同区域、同分项、紧邻有名称的行且有工艺内容时生成带来源的延续候选；必须复核是否为替代方案、续行或独立子件。不要跨区域填充，不能确认时保留缺口转JSON。
- 数量×单价与原金额不一致，尤其原金额为0时，保留两者；不自动把未选方案、未报价行改成收费项。型号缺失留空。
- 多层表头、重复列名或语义不明确时，由 Codex 读取上下行、原图/合并区域后生成标准JSON。不得用一个别名规则声称理解全部非标合同。
- 导入后核对分组行数与总金额；原表三位小数保留在来源，展示舍入不能改写原值。仅输出比价表，不修改原表，也不把新报价写入历史成交库。

## 含图片报价：必须做视觉理解后再匹配

文字提取成功不代表报价已完整识别。用户提交含效果图、结构图、截图或图注的报价时，读取图片并将可确认的信息关联到对应报价行，补入工艺、规格及组合，用于分类与检索。

1. 下载有权访问的原始文件，先区分工作表版本与报价范围。保留原件；不要将旧版、替代方案或分组汇总重复计价。
2. XLSX 可用本 Skill 的 `scripts/extract_xlsx_images.py <原件> --out <证据目录> --sheet <工作表名>` 提取图片和锚点索引，仅用 Python 标准库。此脚本只提取，不执行 OCR 或视觉理解。Codex 必须实际查看联系表及关键原图；PDF、DOCX、单元格图片、外链图或脚本未覆盖的图形，另用对应原生工具/预览提取，不得以返回零张判定无图。
3. 锚点只是候选归属。结合展项标题、合并单元格、图中标签、上下行和结构语义判断；浮图可能错跨行。一图可关联多行，但不能据此重复报价。保留原锚点与复核后的关联理由。
4. 图片明确标注的尺寸、单位、材质、工艺、品牌型号可结构化；效果图只支持可见形态/组合说明，不凭外观认定材料，不从比例猜尺寸。图中门高、安装高度、字高、板厚、外框尺寸分别记录，不能混作产品整体尺寸。 写入可检索规格时保留对象和角色标签，例如“墙面范围：1350×3200mm；中文字高32mm；英文大写字高30mm”；中文大标题、英文副标题与正文也分别记录。安装离地距离保留为安装参数，不能替代物料高度。设计建议与实际报价工艺分别保留，不将建议写成已确认施工。
5. 图中文字与报价文字冲突时分别保存并标明差异，不默认图片优先。合并单元格中的编号必须对应子项，例如“3.字厚”不能附到第1项丝网印；年份不能当型号。价格、数量、零金额及未选方案保持原文，不从效果图虚构价格或数量。
6. 标准JSON每行保留 `original_item_name`、`original_spec`、`original_description`、`image_evidence`（文件/页/工作表/锚点）、`image_observation`。实际采购对象进入 `item_name`，项目/展区放在上下文；已确认图片补充写入 `description`、`spec`、`configuration` 才能参与检索，不能只写在聊天里。
7. 生成清晰的解析表，核验分组行数和金额未改变，更新 `launch --input` 指定文件后确认工作台已读入新版本。仅输出表格，不附长篇采购建议。说明实际检查范围和仍未读清的具体字段，不能声称仅靠提取器已经理解全部图片。

### 单价与参考相关性校验

- 同一报价行数量、计价单位与小计明确对应，原单价为空时，计算小计÷数量，四舍五入保留两位小数，标记“计算值”，保留原小计及原空值；不能覆盖已填写单价（包括0）。多组异规格子件混在一行且没有独立金额时，不把组合总价拆成子件单价。
- “整包”“撤场”“租赁/制作不同”仅是已相关对象的范围差异，不是召回依据。先确认用途、类别、型号、材料工艺或明确组合关系，再标注范围差异。不同采购对象反复出现相同候选时，必须检查真实查询内容、缓存键及相关性门槛，不将重复结果当作全库缺资料。


## 经用户授权的新报价动态入库（2026-11-12）

用户已要求将后续新报价和链接解析后入库：每次完成语义整理，都执行下面的私有报价库流程；这不等于写入历史成交库。早先“不将测试报价入库”的规则只适用于未获授权的测试数据。

1. 枚举所有工作表、隐藏表、附件和图片。逐表由模型判断真实表头、上下级关系、预算版本、汇总、分项、未选备选和甲供零价。原始单元格、公式缓存、图片哈希及锚点完整留存。图片锚点可能偏移，依据画面语义校正关联，保留原锚点。
2. 按实际采购对象命名，展馆、展项、品牌背景不充当物料名。软件、设计、CG工序和服务也是BOM；解析用途、材质、型号、工艺、尺寸和组合。原文、模型归一结果和推断依据分别记录，不把模型推断写成原文。
3. 关联供应商全称、原表别名和证据位置；不得凭近似名称合并公司。未写供应商时留空。预算与供应商报价之间的差额保留，不修改单价凑总价；不把供应商报价变成成交事实。
4. 数量和小计明确对应且单价缺失时计算小计÷数量，保留两位并注明计算；按天/人月计价需要保留额外乘数。原零金额、替代方案、不同尺寸组合不得强行反算或均摊。
5. 输出JSON：顶层 `project,source_url,source_sha256,rows`；每行 `line_id,source_locator,record_role,item_name,description,spec,quantity,unit,unit_price,subtotal,currency,supplier,supplier_basis`。另保留 `hierarchy,parent_line_id,model,brand,components,image_evidence,raw_cells,issues,pricing_periods`。`record_role` 区分 `quote_line,alternative_quote,unpriced_component,budget_version,summary_or_header,internal_cost`；仅已核语义和计价且可比较的明细设 `comparable_price:true`。
6. 在用户的私有数据目录执行：
   `valuation-agent library ingest --database <私有目录>/supplier-quotes.sqlite --input <模型复核JSON>`
   再执行 `library export --database <同一路径> --supplier <供应商全称> --out <核验JSON>` 回读。原文件只读；入库有内容哈希去重和版本留存，同源最新版本不重复累计。
7. 用 `library export --database <路径> --references-only --exclude-source <当前报价source_url> --out <供应商参考JSON>` 导出候选。报价不能匹配自己；新供应商报价必须以“供应商报价参考”显示，不能标成交或已执行。对模型候选逐项核用途、配置、单位、阶段和组合范围，不以类别同名直接认定可比。
8. SQLite为私有持久库，并非浏览器缓存。代码可进公开GitHub，报价JSON、SQLite、原件和图片不可进入公开仓库。远程服务器同步必须单独验证成功；本地入库不等于服务器或飞书已更新。已有远程只读查询凭证不得擅自扩为写入权限。

### 展馆非标术语理解

处理展馆、展陈、装饰、图文、灯光及多媒体报价时，先读 [展馆术语与匹配边界](references/exhibition-terminology.md)。由模型按行理解采购对象、构造层次、工序和规格，在保留原名称的同时填写 `standard_object_name`/`standard_service_name`。共同工艺不代表同一物料；同物异名扩展候选后仍核材料、配置、单位和交付范围。整套与部件只作有方向的范围关联，不能传递为价格等价。不要把背景里的“数字内容”“展墙”变成所有行的分类。未标参数保持缺失，图示与文本分来源保留。


### 品牌体验与数字内容的行业语义

涉及品牌线下体验、互动装置、沉浸场馆、CG广告时，读取 [工作室案例与采购语义指南](references/experience-industry-studios.md)。先判定实体/数字/可运行系统、交付阶段和输入→逻辑→输出→载体，再识别同义、条件相似与整套/部件关系。作品文案里的“装置、雕塑、动态、沉浸”不能脱离上下文直接变成物料类别。官网案例仅是语义证据，不得进入历史报价样本或推造价格、厂家和成交关系。

## 自身来源与报价版本硬规则

- 比价必须传递当前报价的 `source_url`、`source_sha256`，保留每行来源证据。不得去掉来源后把新入库报价当历史参考。`library export --references-only` 必须带 `--exclude-source`；比价服务再次排除同源、同哈希副本和整个报价版本组，整包与子件都适用。
- 同一报价修订沿用稳定 `quotation_family_id`。原链接未变可自动按来源归组；换链接的修订必须结合原件与采购事项明确关联，不能按近似项目名猜组。不同供应商独立报价不要混成一个版本组。
- 各版原文与明细保留，仅当前版进入参考池；旧版本重传不能恢复启用。重复导入和同文件副本不增加独立样本。版本组使用同一 `economic_purchase_group`，采购执行状态不因上传改变。
- 无来源身份的资料不得宣称已通过自身排除检查；先补来源。版本关系不清时保留待核，不将多版一起当独立样本。

### 归类路径与专家复核
归类或修订匹配路径时，读取 [海关方法转化与 QA](references/customs-classification-paths.md)。按实际交付对象、核心功能、整机/部件和同层节点下钻；高价值模块只作证据之一。模型回读原文判断组合范围，不把原产地实质性改变当作税则归类规则，也不把同类当作同价。

远程比价须使用 0.2.17 或更新版本，并保留 source_url/source_token/source_sha256 与报价版本关联标识。拆批请求须携带整份报价的来源集合，不得拿同文件其他分项或旧版本作历史依据。

## 规格与召回专项验收
- 空规格不得等同原件未注明；逐行记录 spec_completeness，区分图片待核、原件待核、设计待定与已确认缺失。
- 图片尺寸记录对应部位，禁止把局部分段拼成整体长宽高；保留图片证据。
- 同图不同采购对象的尺寸必须分离：当前对象尺寸写入 spec，中心柱、底座、相邻展柜等关联构件写入 related_component_dimensions 并保留对象名称与图像来源。关联尺寸不能参与当前对象的尺寸相似度。规格已有值也须检查图中厚度、净深、开口等遗漏，不以非空作为复核完成。
- 对未命中和弱匹配逐行复查同义词、子件、计费单位、范围和召回排序，不以命中数量替代准确性。
- comparison_components 必须含原文 source_text；远程接口不得丢弃；子件参考不能当整包价格。 对“测试、调试、运维、安装、运输等”这类明确列举的综合服务，也应结合语义生成安装调试、运输、运维等检索分项，每项附实际原文片段；没有分项数量和单位时保持缺失。复测时分别检查整包参考与部分服务参考，不能把首次整包未命中解释为库内没有相关服务。
- 新报价与同采购版本排除自身来源；更新后核对运行版本、构建标识、报价 revision 和真实界面，不以构建成功宣称交付。

### 跨行图纸与检索实验复核
- 图片锚点只作为定位线索，必须核对图号、区域、对象标签与报价行。发现跨区域错挂图时保留原锚点与纠正依据；报价文字与对应图纸尺寸有差值时分别记录，不按接近程度擅自统一或猜测公差。
- 图纸锚在设计服务行时，继续检查同一展项的实体物料。按图中对象标签、合并分组和构造关系关联尺寸，记录原图哈希、原锚点和关联理由；不得把装置尺寸当成设计费的面积、工时或图纸数量。
- 区分后缀尺寸轴（3000L×1800W）与电气功率（18W）；未标尺寸单位不默认毫米。截面宽、开口、全域范围分别记录，不混成整体尺寸。
- comparison_components 的 source_text 必须对应实际包含内容；不含、另计、甲供不能当作本项已包含子件。LED灯带只能作为环形灯的发光子件线索，钢构、饰面及控制未对齐时不得比较整套价格。
- 远程结果的 retrieval_corpus 记录历史行数、同源排除数、其他失效版本数、保留行数和可计价候选数；各项应守恒。它是检索资格统计，不是召回率或图片理解覆盖率。旧服务没有该字段时标为未提供，不猜填。
- 原件跳转须同时核对比价候选和合同明细接口。多附件按明细来源标识定位对应附件；有明确附件标识时，不用不相干的合同级链接替代。链接存在不等于接收方有权限，实际打开验收另行记录。
- 去重保留品牌、型号、规格、数量、计价单位、币种、倍数口径及报价版本的区别；名称和金额相同不足以判定重复。重复附件仍应归为同一采购样本。
- 查看每行 retrieval_passes 的实际扫描数、候选数与返回上限。结构化索引全扫描不等于原件/图片完整理解，命中增加不等于准确率提高。针对新增候选逐条核查用途、材料、单位和范围。
- 自身排除同时核对飞书分享URL、文件token、文件哈希和报价版本组。别名链接不可导致自己的报价重新进入参考池。

### 零数量历史报价
原件有单价但数量为0时，保留原单价并标注“零数量报价”；不将其当作已执行成交或直接可比价格。不能把缺失数量当作0，也不能仅凭0断言免费或确定未选购。

组合子件召回：当原文明确写钢结构框架时，可用钢结构、钢架、钢骨架等同义表达寻找子件参考。保留原文片段与所属整项；不能把屏体支撑、拆除、结构计算服务直接作为同义项，也不能把子件价格分摊成整项报价。零召回需检查语义筛选原因，不直接断言历史库无记录。

子件未命中复查：用标准采购对象做一次定向检索，例如环形座椅未命中时查座椅，并核对候选形态、材质、计费单位和范围。标准类别有候选而子件无候选时，记录为疑似漏召回，不能归因为无历史资料；运输、拆除、维修等针对该物料的服务不等于物料本体。同类子件仍按部分参考展示，不继承整项金额或数量。

报价文字与设计图尺寸冲突时，保留两组原值并设置 `spec_review.status: source_conflict`。CLI 和网页查询传递 `spec_status: source_conflict`，保留历史参考但不判为无差异直接可比；不得用非空规格覆盖冲突状态。

同一报价行含多个明确对象时，规格用 `【对象：原图对象名称或图号】` 分段保留。参数解析按对象分别比较；对象对应关系不明确时保持缺失，不把两个对象的高度合并，也不凭相近数值认定为同一部位。

蚀刻/雕刻标识须分别记录基材厚度与加工深度，例如“金属板厚度0.5mm；文字蚀刻深度0.15mm”。板厚一致不代表工艺一致，比较时分别核对两者；不得把蚀刻深度当成字高或板厚。

### 旧报价兼容验收
升级后必须保留浏览器中的旧报价和复核记录。聊天导入记录可能没有 `projectId`：按未关联项目处理，不删除记录、不猜项目编号；检查首页、导入窗口和统计均能打开。新 handoff 记录给报价及其明细写入一致的未关联标识，避免旧数据导致整页崩溃。

### 报价版本：默认最新上传，用户说明优先
- 同一供应商、项目、报价范围沿用一个 `quotation_family_id`，前端保持同一报价编号。换链接也要沿用这个编号；可用经核实的 `supplier_id`、`project_id`、`quotation_scope_id` 自动生成。不同方案、区域不能误合并。
- 默认 `version_intent=latest`：新内容入库即启用，旧版归档。用户说“上个版本”“上上个版本”“旧稿”等，解析为 `version_intent=historical`，保留用户原话为 `version_note`，只归档不覆盖当前报价。修订日期和序号保留为证据，不自动推翻用户规定的默认上传顺序。
- 后台 `internal_version` 按每组入库顺序编号（1）、（2）等，它不是业务修订先后结论。前端报价编号不加版本后缀。相同内容重复导入不重新启用旧版。
- 入库回读 `activation`；`activated` 表示启用，`historical_archived` 表示仅存档。版本列表命令：`valuation-agent library versions --database <私有目录>/supplier-quotes.sqlite`。
- 当前报价比价时排除整个版本组。默认导出仅当前版，不把旧版作为额外样本。

### 全库原件跳转核查
核查范围须同时覆盖全部历史报价行及全部台账附件（包括没有报价明细的合同）。飞书附件类型12按文件处理，22按云文档处理。报价来源是图片时，只有存在确切原合同附件编号、图片定位及“同一报价可见于合同内嵌图”的核对依据，才跳转该合同；不能用同项目任意附件代替。链接解析成功、远端有权限打开、原件字段核对完成是三个独立状态，分别记录，不能相互替代。

计算单价的依据必须随 JSON 和 Excel 交付保留：显示参与计算的总额、计费数量、单位和原报价/优惠口径，不能仅导出最终数值。整包总额仍放总额列，不转入单价列。

### 首轮多参考检索
首轮同时检索名称、用途、工艺、规格及有原文依据的子项；先查询整项，再补充子项。不得按固定条数截断有效依据。按交付对象及范围、材质工艺规格、计价口径、参数完整度排序，整包及部分参考后置。排除当前来源及其版本，沿用采购证据去重。返回 match_rank 和具体 match_points，网页初显五条并允许展开全部，不得另行改变引擎排序。
